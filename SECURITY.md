# Security reporting

If you find a payment-verification or access-control issue, contact the maintainer privately through an established channel. Use GitHub's private vulnerability reporting option if it is available for this repository.

Include the affected version, steps to reproduce and the likely impact. An anonymised example is enough; keep API keys, customer information and real transaction details out of reports.

The maintainer has tested live payments successfully. Further checks focus on unusual callback timing, payment recovery and different form configurations. See the [README](README.md#testing-and-issues-being-checked) for the current review findings.
